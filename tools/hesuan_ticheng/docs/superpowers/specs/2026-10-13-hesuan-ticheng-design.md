# 利润核算自动化程序设计

日期：2026-10-13

## 目标

在 `E:\project\crossborder-tools\tools\hesuan_ticheng` 中提供一个可重复运行的利润核算程序。用户把新的主表、采购订单表和可选商品表放入目录后，运行一次程序即可生成新的订单利润核算 Excel，不修改原始数据。

## 输入文件

- 主表：文件名以 `导出订单包裹` 开头的 `.xlsx` 文件。选择修改时间最新的文件。
- 采购表：优先读取 `采购订单.xlsx`；如果不存在，允许读取 `采购订单.csv`。
- 商品表：优先读取 `商品表.xlsx`；不存在时跳过商品成本匹配，不把缺失成本当作零。

程序通过列名别名和必要的列位置兜底识别字段，处理 Excel 导出中可能出现的 BOM、GBK/GB18030、零宽字符和首尾空格。

## 核算规则

1. 主表每一行是一条主订单，使用主表订单编号作为输出粒度。
2. 采购订单号去掉末尾的 `-数字` 得到基础订单号。基础订单号相同的无后缀记录、`-1`、`-2` 到 `-n` 记录全部归并。
3. 采购订单状态包含“退款”“拒绝”或“驳回”的记录不计入采购成本、采购数量和利润。程序同时保留这些记录的数量、子订单号和金额供核对。
4. 采购成本优先使用归并后的有效采购记录中的“采购总金额”合计。
5. 当订单没有有效采购成本时，使用主表商品 ID 匹配商品表。商品成本合计为商品表“产品成本($)”乘以主表“商品数量”。
6. 物流成本按实际履约单数计费：每个纳入计算的采购子订单扣 1 美元；没有有效采购子订单、仅通过商品表兜底的主订单按 1 个实际履约单扣 1 美元。
7. 订单利润公式为：

   `订单利润 = 平台回款金额 - 采用成本 - 物流成本`

   `物流成本 = 有效采购子订单数 × 1 美元`；若使用商品表兜底且有效采购子订单数为 0，则物流成本为 1 美元。

8. 如果采购成本和商品成本都缺失，订单利润留空，并标记待核对，不使用零成本替代。

## 输出文件

程序在 `输出` 子目录生成带时间戳的 `.xlsx` 文件，至少包含一个“利润核算”工作表，包含：

- 主表订单字段：订单号、回款金额、订单时间、店铺、商品 ID、商品数量、商品描述。
- 采购匹配字段：计入采购行数、排除采购行数、计入/排除子订单号、采购商品数量、采购成本、排除金额。
- 商品表字段：商品表匹配行数、商品成本单价、商品成本合计。
- 计算字段：采用成本、物流成本、订单利润、成本来源、核对状态。
- 汇总区：主表订单数、采购匹配数、商品成本匹配数、待商品表数、空订单号数、计入/排除采购行数、排除采购金额和已核算利润合计。

输出文件使用文本格式保存订单号和商品 ID，避免长数字被 Excel 显示为科学计数法。原始输入文件保持不变。

## 核对状态

- `已匹配采购订单`
- `已匹配商品成本`
- `未找到采购订单，待商品表`
- `仅有退款/拒绝采购记录，待商品表`
- `订单编号为空，待核对`
- `已找到采购订单但成本缺失`

## 使用方式

提供：

- `hesuan_ticheng.py`：主程序和可测试的核算函数。
- `运行利润核算.bat`：在当前目录启动程序，输出文件写入 `输出`。
- `test_hesuan_ticheng.py`：不依赖真实文件的规则测试。
- `README.md`：安装依赖、运行方式、输入表要求和状态说明。

推荐运行方式：在目标目录双击 `运行利润核算.bat`，或执行 `python hesuan_ticheng.py`。

## 错误处理

程序在开始时检查主表、采购表和可选商品表。缺少必要文件、必要列、无法解析金额或发现商品 ID 重复且成本不一致时，输出清晰错误信息并停止生成误导性结果。可选商品表缺失不阻止程序运行，但会把未匹配订单标记为待商品表。

## 测试范围

测试覆盖：

- 基础订单与 `-1/-2` 子订单归并并合计成本。
- 退款、拒绝和驳回状态排除。
- 采购成本优先于商品成本。
- 商品成本按单价乘数量兜底。
- 每个主订单只扣一次物流费。
- 缺失订单号、缺失成本、重复商品 ID 和无商品表时的状态。
- 运行当前目录真实数据，核对输出行数、匹配数、商品表试算订单和利润汇总。
