# 配送异常 SKU 处理工具设计

## 目标

提供一个 Windows 桌面工具，让运营人员选择异常汇总表和 SKU 源表，按商品与店铺分组预览配送异常，并在确认后通过妙手 ERP 接口删除异常 SKU 或下架无可保留 SKU 的商品。工具生成新的结果工作簿，不覆盖原始文件。

## 范围与规则

- 只处理总状态精确等于“配送需检查”或“价格和配送均需检查”的记录。
- 单独“价格需检查”不处理，价格修改功能暂不启用。
- 正常 SKU 不在异常表中，必须从详情返回的完整 SKU 列表保留。
- 一个商品组只查询一次详情并一次性提交，避免逐 SKU 修改。
- 多 SKU 商品删除目标 SKU；仅剩一个异常 SKU 的商品调用商品下架接口。
- 详情失败、店铺映射缺失、SKU ID 与平台 SKU 不一致时跳过并标记手动处理。
- Cookie/token 只在运行时输入，不写入文件、源码或日志。

## 界面

采用 Python Tkinter/ttk 实现的深色卡片式桌面界面。顶部显示产品标题和运行状态；输入区提供两个 Excel 文件选择框、输出路径、Cookie/token 密码框及“加载并预览”按钮；预览区用表格显示商品组、异常 SKU 数量、拟执行动作和校验状态；底部提供确认执行按钮、进度条和滚动日志。

## 数据流

1. 读取异常汇总和源表，按 SKU ID 关联店铺 ID。
2. 过滤配送相关状态并按全球产品 ID+店铺 ID 分组。
3. 预览阶段只读取本地表格，不调用修改接口。
4. 执行阶段逐组查询详情，核对目标 SKU，构造完整 SKU 编辑载荷。
5. 多 SKU 调用 `saveEditItem`；单 SKU 调用 `updateItemStatusForsale`。
6. 将每个异常行的计划操作、接口结果和失败原因写入新工作簿 `处理结果`。

## 验收标准

- 未输入 Cookie 或未选择文件时不能执行。
- 预览数字与本地表格过滤结果一致。
- 执行过程可取消后续任务并实时显示进度。
- 任何失败组都不影响其他组，且结果表明确标记“需手动处理”。
- 启动说明、依赖和安全注意事项写入 README。
