# TikTok 排行榜到 Amazon 妙手采集 Skill 设计

## 目标

创建一个可自动发现的个人 Codex Skill，用于用户提供 TikTok 商品排行榜后，完成候选排序、Amazon 美国站以图搜款、结果筛选、商品详情核验和妙手采集。Skill 应沉淀本次闭环中非直观的浏览器行为和失败模式，同时保留用户对阈值、采集范围、品牌处理和后台核验方式的决定权。

## 触发边界

Skill 在用户希望从 TikTok 排行表、热销数据或类似选品表中挑选商品，并需要在 Amazon 美国站通过图片查找同款、筛选结果或用妙手采集时使用。

以下情况不应自动扩展任务：

- 用户只要求分析表格，不要求浏览器操作。
- 用户只要求普通 Amazon 搜索，不涉及 TikTok 候选或妙手采集。
- 用户没有授权采集时，不应因为识图成功而自动创建妙手侧数据。
- Skill 不自行决定去除品牌、Logo、修改商品内容或发布商品。

## 核心工作流

1. 读取用户提供的排行榜，确认实际工作表、数据范围和字段语义，不修改源表。
2. 依据用户指定的优先级生成候选池。默认将当前排名和最高点击量视为核心信号，成交金额、点击率、评分和评价作为辅助信号。
3. 对不同细分类目做类目内归一化；按图片 URL、明显同款和已提供的历史 ASIN 清单去重。
4. 下载候选图片到可上传的本地路径，并在用户指定的 Chrome 中打开 Amazon 美国站。
5. 确认配送邮编；默认沿用本次的 `91730`，但以当前用户要求为准。
6. 使用卖家精灵图片入口上传图片。上传前记录当前 Chrome 顶层标签页；上传后查找新出现的 `amazon.com/stylesnap?q=local` 标签并接管。
7. 从 StyleSnap 结果页读取所有可见或可访问的商品卡片，比较商品结构、ASIN、评分、评价数、价格、BSR、配送方式和 Prime 配送时长。
8. 先判断是不是同一个商品或同等套装，再应用硬阈值。默认 Amazon 评分严格大于 4.0、评价数严格大于 20；配送门槛以用户当前要求为准。
9. 在多个合格候选之间，优先同款程度、履约速度、类目排名、评价规模和月销量。软性信号不得覆盖同款判断和用户的硬条件。
10. 需要详情核验时，从结果页进入候选详情；商品通常会在新标签打开，应重新从 Chrome 顶层标签中定位并接管。
11. 用户授权采集后，点击妙手“采集此商品”。是否进入妙手后台核验由用户决定；如果用户要求只执行采集，不额外查询采集箱。

## 候选选择规则

`references/candidate-selection.md` 保存可复用的选择原则：

- TikTok 默认权重基线：当前排名 30%、最高点击量 30%、最高成交金额 20%、最高点击率 10%、评分与评价 5%、图片可识别度和结构清晰度 5%。
- 权重是基线，不覆盖用户的新要求。
- “同一个东西”优先于纯数据最优。例如三支扭力扳手套装不能被单支扳手替代，完整生存套装不能在未说明的情况下被普通战术背包替代。
- Amazon 默认硬条件：评分 `> 4.0`、评价数 `> 20`、当前规格有库存、针对目标邮编满足用户的最晚送达要求。
- BSR、过去一个月购买量、价格和卖家数量是软性排序信号。
- 日期范围按范围终点判断；切换规格或卖家后重新核验。

## 浏览器与插件关键经验

`references/browser-and-collection.md` 保存本次验证出的非直观行为：

- 图片上传成功后，结果页可能在新的 StyleSnap 顶层标签中出现，而原 Amazon 首页继续显示上传提示。
- 不得用“拖拽或点击图片上传”文字是否存在判断结果是否生成。
- 正确方法是比较上传前后的 `chrome.user.openTabs()`，识别新出现的 `/stylesnap?q=local` 标签，随后 `claimTab` 并读取截图和 DOM。
- 不需要用户重复截图。截图用于视觉核对，DOM 用于批量提取 ASIN、评分、评价数、BSR 和配送时长。
- StyleSnap 商品链接和 Amazon 商品详情经常打开新标签；点击后应再次检查顶层标签，而不是只等待当前标签导航。
- 妙手侧栏可能位于扩展注入层，普通 DOM 定位不到按钮时，应以当前截图确认按钮位置，再通过浏览器坐标点击。
- 妙手加载动画只证明采集请求被触发，不能证明采集箱中一定生成记录。
- 若用户要求验证，必须区分“采集按钮已点击”“请求已结束”“后台记录已生成”三个状态；若用户要求只管采集，则完成点击并等待请求结束后停止。
- 重复采集控制优先使用用户后续提供的历史 ASIN 清单，不擅自依赖标题模糊匹配。

## 异常处理

- 找不到图片结果时，先检查是否出现新的 StyleSnap 顶层标签，不进行长时间盲等。
- 图片结果只匹配到局部物体时，明确说明匹配的是局部商品还是完整套装；不得把局部匹配静默当成完整同款。
- 结果卡片的 Prime 时长只用于初筛；用户要求精确日期时，在商品详情页按目标邮编核对 Amazon 原生送达日期。
- 普通 DOM 看不到妙手按钮时，先截图确认扩展层状态，不重复盲点。
- 采集请求出现加载动画后不重复点击，避免潜在重复采集。
- 妙手出现店铺、站点、字段覆盖或发布选择时，只有在用户已有明确授权和选项时继续，否则停下请求方向。

## 测试与验证

在创建 Skill 前运行一个无 Skill 的基线场景，观察测试代理是否会：

- 在原 Amazon 首页盲等，而没有发现新的 StyleSnap 标签。
- 把上传提示仍存在误判为没有结果。
- 只按评分或排名选择结构不一致的商品。
- 把加载动画报告为采集成功。

创建 Skill 后用相同场景复测，再加入一个变体场景：结果页同时存在数据更好但结构不一致的商品，以及数据略弱但完整同款且次日达的商品。预期代理选择完整同款，并正确区分采集触发和采集成功。

最后运行 Skill Creator 提供的 `quick_validate.py`，检查目录名、YAML frontmatter、资源引用和未完成占位符。测试只读取模拟场景，不操作真实 Amazon 或妙手账户。

由于当前协作规则不允许未经授权使用子代理，只有用户批准本设计中所述的独立测试代理后，才执行基线和复测代理；否则改用结构校验和人工场景审查，并明确测试范围限制。

## 成功标准

- Skill 能在相关请求中被准确发现，不吸引普通表格分析或普通 Amazon 查询。
- 入口文件简洁，详细规则按需从两个参考文件加载。
- 新代理能独立发现 StyleSnap 新标签，不需要用户提供结果截图。
- 新代理先判断同款，再比较评分、评价、配送和排名。
- 新代理不会把上传提示、加载动画或按钮点击错误表述为最终采集成功。
- Skill 通过结构验证，引用路径有效，没有占位符或项目临时文件依赖。
